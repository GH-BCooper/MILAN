## Column contracts

The seed script (`seed/index.ts`) reads exactly these columns. Add rows freely;
do not rename columns without changing the script.

### districts.csv
`code,name,name_hi,lat,lng,vulnerability_index`
`code` is a 3-letter district code and is the second-to-last segment of every
tracking ID issued in that district (`JH-2026-GUM-0042`).

### blocks.csv
`code,district_code,name,name_hi,lat,lng,vulnerability_index`
`district_code` must exist in `districts.csv`.

### heis.csv
`hei_code,name,slug,district_code,lat,lng,website`
`slug` must be unique — the organisation plugin requires it.

### capabilities.csv
`hei_code,department,lab_name,specialisation_tags,faculty_name,faculty_designation,declared_capacity,capacity_from,capacity_to`
`specialisation_tags` is semicolon-separated. These tags are what S5 routes
against in Phase 2, so they matter more than they look.

### challenges.csv
`title,body_original,body_lang,body_en,district_code,block_code,lat,lng,people_affected_bucket,recurrence,urgency_self_report,reporter_name,seed_status,corroborations`

- `body_lang` is `hi` or `en`. When it is `en`, leave `body_en` empty — the
  script copies `body_original` across.
- `people_affected_bucket` is one of `1-10`, `10-100`, `100-1000`, `1000+`,
  stored as the bucket midpoint.
- `recurrence` is one of `one-off`, `seasonal`, `yearly`, `constant`.
- `seed_status` is `SUBMITTED` for almost every row. Three rows are seeded at
  `CLOSED` or `CITIZEN_VERIFIED` with backdated timestamps so that `/stats` is
  not empty on stage.
- `corroborations` is how many extra people reported the same thing.
