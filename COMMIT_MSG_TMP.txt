phase1/task6: the six-step intake wizard

/submit is a six-step wizard: text with a language toggle, optional photos,
location, scale, framing, review. State lives in one reducer and is written to
localStorage on every change under milan:draft:<id>, so a dropped connection
does not cost a citizen four screens of typing.

- Photos are uploaded through the server, NOT by presigned direct upload as the
  build file suggested. EXIF stripping has to happen somewhere the citizen
  cannot skip; a direct upload would put the camera's GPS in our storage first.
  sharp re-encodes without a metadata block and the object key is the SHA-256 of
  the resulting bytes.
- Face and plate blurring is not implemented. The UI says so to the citizen and
  challenge_media.faces_blurred records false rather than claiming otherwise.
- Location: geolocation, a MapLibre pin, and district/block dropdowns that
  override both. Resolution is nearest-centroid, not point-in-polygon, and
  lib/geo/nearest.ts says so and says why.
- The map degrades to markers on a blank canvas when NEXT_PUBLIC_PMTILES_URL is
  unset or the archive is unreachable. Nothing on the demo path may depend on a
  tile server answering.
- Rate limit: 5 submissions/hour by IP and user, counted in audit_log because an
  in-memory counter on serverless does not exist.
- /api/intake and /api/intake/media call the same server action, for non-browser
  clients and for the verification harness.

Verification: scripts/verify-submit.mjs, 23/23. It writes real GPS EXIF into a
fixture JPEG, uploads it, downloads the stored object back and proves the EXIF
is gone.
