The pool bug
  drizzle's postgres-js driver issues every statement through postgres.js
  unsafe(), which is not pipelined. With the max:1 connection the usual
  serverless advice recommends, two queries started concurrently deadlock, and
  because the client is shared the instance then hangs on every later request.
  /stats and /submit both wedged the server on first load.

  lib/db/index.ts now takes a real pool (DATABASE_POOL_MAX, default 8) against
  the Supabase transaction pooler, which is what that pooler is for.
  lib/db/raw.ts adds execRaw(), a serialising queue for raw analytics queries:
  the pool is the fix, the queue is the seat belt.
